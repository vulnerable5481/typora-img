**<font color='blue'>存储单元  与   内存单元   的一些异同</font>**

 **内存单元（Memory Cell）**

内存单元是指 **计算机内存**（通常指 RAM）中的基本存储单位。它通常是一个可以存储一个数据值（如 1 位、1 字节等）的硬件单元。每个内存单元都有一个唯一的地址，用于标识和访问该内存位置。

内存单元的工作原理：

- **存储数据**：内存单元通过某种方式存储数据（如电荷、磁性状态等），通常存储的是二进制信息（0 或 1）。
- **存取操作**：通过访问内存单元的地址，CPU 可以读取或写入数据。
- **大小**：<font color='blue'>大多数计算机的内存单元为 1 字节（8 位），即每个内存单元通常表示一个字节的数据。</font>
  - 比如200:0处的内存单元，只能存最多 1字节的数据  十六进制范围表示：00~~ff




 **存储单元和内存单元的差异**

尽管这两个术语有相似之处，它们的使用背景和具体含义有所不同。以下是主要的差异：

| **特性**     | **存储单元**                               | **内存单元**                                         |
| ------------ | ------------------------------------------ | ---------------------------------------------------- |
| **定义**     | 存储数据的基本单位，通常指数据存储位置     | 特指计算机内存中的存储单元，通常是一个字节或更小单位 |
| **范围**     | 可以指计算机的任何存储介质，如内存、硬盘等 | 通常只指计算机中的内存（RAM）                        |
| **大小**     | 大小可以变化（通常为字节、字、块等）       | 通常为 1 字节（8 位）                                |
| **存储介质** | 可用于表示内存、硬盘、光盘等多种存储介质   | 主要指内存（RAM），不包括硬盘或其他存储介质          |
| **用途**     | 用于存储不同类型的数据，如程序、文件等     | 主要用于存储 CPU 需要快速访问的数据                  |





## 2.分段寻址机制

**<font color='red'>分段寻址的目的是 确定物理地址！</font>**

**<font color='blue'>*16 在 二进制是左移4位，但是在十六进制是左移1位，别搞混了！</font>**

- 问题1的引出：8086内部运算地址只有16位(二进制)，但是物理地址5位（十六进制），如何解决寻址空间上的矛盾？
- 问题2的引出：为什么物理地址要设计5位(5位是十六进制，换算成二进制是20位)，而不是4位？
- 问题3的引出：什么是段地址？什么是段地址的基地址？什么是物理地址？什么是偏移地址？
- 问题4的引出：为什么要设计段地址*16 + 偏移地址 = 物理地址 这个公式？好处在哪里？
- 问题5的引出：段地址的值是根据段寄存器获取的，什么是段寄存器？有那些种类?

```
问题1的解答：通过段地址左移4位(*16) + 偏移地址  这样就变成了一个20位的地址，可以任意访问整个1MB的存储空间！
问题2的解答：就好比你给一个数据划分内存，肯定是刚好差不多就可以，过大过小都不好，选择5位自然是大佬实践得出的真理！不要抬杠！
问题3的解答：
		段地址：是一个16位的值，段地址 是由段寄存器（如 CS、DS、SS、ES）的值决定的。段地址本质上是指向内存中某个段的基地址
			   段地址的值是根据段寄存器获取的。
		基地址：是段的起始地址（即段地址左移四位就是基地址）。通过基地址与偏移地址的结合，8086 生成了 20 位的物理地址。
		物理地址：每一个内存单元在内存空间中都有唯一的地址，这个唯一的地址被称为物理地址
		偏移地址：相对于段起始地址（基地址）的偏移量，表示在某一个段内的具体位置，用于定位段内的某个字节数据。
问题4的解答：通过段地址左移4位(*16) + 偏移地址  这样就变成了一个20位的地址，可以任意访问整个1MB的存储空间！
		   还可以给不同的段分配不同的功能。
问题5的解答：
		段寄存器是 8086 处理器中专门用于存储`段地址`的寄存器，负责指向内存中的不同段（如代码段、数据段、堆栈段等）的起始地址。		  每个段寄存器都是 16 位宽，与偏移地址结合后生成 20 位物理地址，用于访问实际的内存单元。
		
		通过下面这些寄存器，8086 实现了对1MB 内存空间的灵活管理和访问。
        CS（代码段寄存器）：指向当前程序代码所在的段。
        DS（数据段寄存器）：指向全局数据或变量所在的段。
        SS（堆栈段寄存器）：指向堆栈所在的段，用于函数调用、返回值等。
        ES（额外段寄存器）：指向额外的段，用于特殊操作（如字符串处理）。
```

## 6. 代码段声明数据

- <font color='red'>**问题**</font>：之前我们都是直接操作 内存地址，但实际上有的内存地址我们不应该随便操作，操作不当可能使错误数据代码出现在不该出现的内存地址。因此，直接操作内存地址有潜在的风险。

- **<font color='red'>解决</font>**：我们使用 `dw`（define word）指令来声明数据，操作系统会自动为这些数据分配内存地址

  - **`db`** 定义 1 字节的数据（8 位）   define byte
  - **`dw`** 定义 2 字节的数据（16 位）define word
  - **`dd`** 定义 4 字节的数据（32 位）define doble
  - **`dq`** 定义 8 字节的数据（64 位）
  - **`dt`** 定义 10 字节的数据（80 位）

  **<font color='blue'>这些伪指令都是用来分配内存空间并初始化数据的。你可以根据需要选择适当的伪指令，来定义适当大小的数据项</font>**。

  ```
  使用哪一个指令声明？db,dw这么多，我可以随便用吗？
  答：比如字符都是1字节的，我们肯定得用db声明字符相关的，其他的我也没摸清楚
  ```

- **<font color='red'>新的问题</font>**，但是上面的代码依然有问题，那就是声明数据也占内存,我们无法知道哪里是声明的数据，哪里是将要执行的代码

- **<font color='red'>解决</font>**：为了确保程序能够从正确的地址开始执行，我们需要使用汇编中的 `START` 标签，并在程序的 `END start` 指令中指定程序入口点

  - ```
    code segment
        
    start:   ;start 用来声明 程序从此处开始
        mov ax, 0x4C00  
        int 21h
    code ends  
    
    end start   ；end start 声明 程序的结束
    ```

  - 为什么 `start` 和 `end start` 不需要包围 `code segment` 和 `code ends`???????

- 详解

  ```
  OF：overflow(是否溢出)   特指在有符号运算，结果范围，发生了溢出
  DF：direct(方向),				
  TF: trap(陷阱)		   用于单步中断
  SF: 					有符号运算中，0为正，1为负；无符号则无意义
  ZF: zer0(零)    		   计算结果是否为0
  PF: parity(奇偶)	 	  判断所有二进制位中的1的个数，1的个数为偶数，PF=1，反之,PF=0
  CF：carry(进位/借位)	    特指无符号运算，超过范围，需要进位；也表示减法的时候，需要借位
  ```

## 14. 实验

方法 letterc :将一个字符串（包含任意字符，以0结尾）中的小写字母变成大写



```
assume cs:code, ds:data

data segment
    db 'cl3za1db',0
code segment
main:
    mov ax,data
    mov ds,ax

    call letterc

    ; 退出程序
    mov ax, 4c00h
    int 21h

    letterc:
    push si

    ; while循环字符串判断每一个字符是否是小写字母
    mov si,0
    while:
    ; 判断是否 >= 97
    mov ax,ds:[si]
    cmp al,97
    jnb isless
    jmp short notlowercase

    ; 判断是否 <=122
    isless:
    cmp al,122
    jna tobeuppercase 
    jmp short notlowercase

    ; 将小写字母大写
    tobeuppercase:
    and al,11011111b
    mov ds:[si],al

    ; 若不是小写字母，则直接跳到下一个字符
    notlowercase:
    mov cl,al
    mov ch,0
    inc si
    jcxz ok
    jmp short while

    ; while循环结束
    ok:
    pop si
    ret


code ends
end main
```

## 3. 标号

- **分类**

  - **地址标号**：我们之前用的   s:   loop s  这里的s 就是地址标号，指向一个地址
  - **数据标号**:   data segment里面的   a dw 1,2,3,4,5,6,7,8   这里的a就是数据标号

- **数据标号详解**

  - ```
    data segment
    	a db 1,2,3,4,5,6,7,8
    	b dw 0
    	c:dw 0
    data ends
    
    mov al,a  这里默认就是字节
    mov bx,b  这里默认就是字
    mov b,2 等同于  mov word ptr ds:[8],2   由于使用数据标号极大地提高了效率！
    而且  a[3]就直接操作了ds:[3]的数据，非常的方便！！
    ```

  - 上面的 a 和 b 就是数据标号，a代表地址为 data:0, 长度为字节的内存单元，b代表地址为data:8,长度为字的内存单元

  - 上面的c 不是数据标号，而是地址标号，没有指出长度！**也就是说两个标号的区别就是数据标号同时指明内存地址和单元长度**

  - **拓展：标号当做数据**

    ```
    data segment
    	a db 1,2,3,4,5,6,7,8
    	b dw 0
    	c dw a,b   ; 等同于 c dw offset a, offset b 相当于二级指针（就是只想数组的指针），这样极大地简化了代码
    data ends
    ```

  - ③  IF、TF = 0

## 2. 除法溢出实验

- **<font color='blue'>如果有疑问，就去看书，书上解释得非常透彻，我这里只解释几点</font>**

1. **中断触发程序do0被保存在哪里？**答案：起始地址为0:200的连续内存单元中，原因就是这块地址**一般没人用**
2. **overflow! 这个字符串要保存在do0里面！** 原因：保存在外面程序一旦结束，就可能清空，保存在do0才能持久存在
3. **为什么要do0里面要jmp?** 答案：看代码注释
4. **为什么没有“保护现场”等操作？** 原因：本实验只需关注最关键的地方即可
5. **<font color='red'>退出程序的解密</font>**  ：  实际上 mov ax,4c00h; int 21h 就是返回操作系统的意思

```
assume cs:code, ds:data

data segment
data ends

code segment
main:
    ; 安装do0程序 
    mov ax,cs
    mov ds,ax
    mov si,offset do0  ; ds:si 指向do0程序
    mov ax,0
    mov es,ax
    mov di,200h   ; es:di 指向目标地址
    mov cx,offset do0end-offset do0   ;  这行代码计算了do0程序的长度
    rep movsb

    ; 设置中断向量表
    mov ax,0
    mov es,ax
    mov word ptr es:[0*4],200h
    mov word ptr es:[0*4+2],0

    ; 触发 除法溢出中断程序
    mov ax,1h
    mov bx,0
    div bx

    ; 退出程序
    mov ax, 4c00h
    int 21h

    ; do0中断程序
    do0:
    jmp short do0start   ; 这里跳转是因为不想让下面定义的数据被当做代码执行
    db 'overflow!',0     ; 这行数据的真实位置位于 cs:202h 

    do0start:
    ;显示字符串 overflow
    mov ax,cs
    mov ds,ax
    mov si,202h    
    mov ax,0b800h
    mov es,ax
    mov di,12*160+36*2  ; 设置字符串显示在中央位置
    
    ; 显示字符串'overflow!'在中央位置
    mov cx,9
    s:
    mov al,ds:[si]
    mov es:[di],al
    inc si
    inc di
    mov byte ptr es:[di],02h  ; 设置字体颜色为绿色
    inc di
    loop s

    mov ax,4c00h
    int 21h
    do0end:
    nop


code ends
end main

```





## 3. 单步中断

- **<font color='red'>单步中断的作用：</font>**实现单步跟踪程序的执行过程，方便程序员调试代码。  这也是debug的实现思想之一
- **有一个问题：CPU执行完一条指令，检测到TF为1，产生单步中断，引发中断过程，然后执行中断处理程序。但是，在执行中断处理程序，为什么要将已经是0的TF 改为1呢？**  原因：中断处理程序也是一条条指令组成，如果TF依然是1，那执行中断处理程序的第一条指令又因为检测到TF为1，引发中断过程，然后执行中断处理程序，这样就死循环了，所以在进入中断处理程序前要设置TF=0

## 10. int9实验

- **此处我们用PC键盘处理过程，来真实地处理外中断！**

- **<font color='blue'>要求：修改原先的int9中断例程，自己设计一个newint9,使屏幕中不断闪烁的a~z,实现按下esc键盘让字符变颜色</font>**

- **<font color='red'>这一块你自己看书去吧，书上解释得非常到位，我这里只简单罗列代码</font>**

- ```
  assume cs:code, ds:data,ss:myStack
  
  data segment
      dw 0
  data ends
  
  myStack segment
      db 128 dup (0)
  myStack ends
  
  code segment
  main:
      mov ax,myStack
      mov ss,ax
      mov sp,128
  
      ; 安装定制的int9 到 0:200h 
      mov ax,cs
      mov ds,ax
      mov si,offset newint9
      mov ax,0
      mov es,ax
      mov di,200h
      mov cx,offset newint9end-offset newint9
      rep movsb
      ; 要先将原先的int9的入口保存在别的地方（此处我们选用data:0 , data:2保存）
      push es:[4*9]
      pop ds:[0]
      push es:[4*9+2]
      pop ds:[2]
      ; 设置中断向量表 【提示：在设置的时候需要屏蔽可屏蔽中断！不然你在设置中断向量表的时候，有个键盘外中断就会指向错误地址】
      cli
      mov word ptr es:[4*9],offset newint9
      mov es:[4*9+2],cs
      sti
  
      ; 展示 a ~ z
      mov ax,0b800h
      mov es,ax
      mov ah,'a'
      s:
      mov es:[160*12+40*2],ah
      call delay
      inc ah
      cmp ah,'z'
      jna s
  
      ; 展示结束，需要恢复int9
      mov ax,0
      mov es,ax
      push ds:[0]
      pop es:[4*9]
      push ds:[2]
      pop es:[4*9+2]
      
      ; 退出程序
      mov ax, 4c00h
      int 21h
  
      ; 延时函数
      delay:
      push dx
      push ax
      mov dx,10h
      mov ax,0
      s1:
      sub ax,1
      sbb dx,0
      cmp ax,0
      jne s1
      cmp dx,0
      jne s1
      pop ax
      pop dx
      ret
  
      ; 定制的int9中断例程：实现按下esc键，修改显示的颜色
      newint9:
      push ax
      push bx
      push es
  
      ; 读取 键盘数据
      in al,60h
  
      pushf   ; 标志寄存器入栈
      pushf   ;  IF、TF = 0
      pop bx
      and bh,11111100b
      push bx
      popf    
      call dword ptr ds:[0]  ; 调用原先的int9实现cs、ip入栈，计算(cs)、(ip)还有一些硬件细节
  
      ; 实现按下esc键，修改显示的颜色
      cmp al,1   ; esc的扫描码就是 1
      jne newint9end
  
      mov ax,0b800h
      mov es,ax
      inc byte ptr es:[160*12+40*2+1]   ; 属性加一，修改颜色
  
      newint9end:
      pop es
      pop bx
      pop ax
      iret
      
  
  code ends
  end main
  
  ```
