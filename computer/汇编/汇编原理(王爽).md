**<font color='blue'>存储单元  与   内存单元   的一些异同</font>**

 **内存单元（Memory Cell）**

内存单元是指 **计算机内存**（通常指 RAM）中的基本存储单位。它通常是一个可以存储一个数据值（如 1 位、1 字节等）的硬件单元。每个内存单元都有一个唯一的地址，用于标识和访问该内存位置。

内存单元的工作原理：

- **存储数据**：内存单元通过某种方式存储数据（如电荷、磁性状态等），通常存储的是二进制信息（0 或 1）。
- **存取操作**：通过访问内存单元的地址，CPU 可以读取或写入数据。
- **大小**：大多数计算机的内存单元为 1 字节（8 位），即每个内存单元通常表示一个字节的数据。



 **存储单元和内存单元的差异**

尽管这两个术语有相似之处，它们的使用背景和具体含义有所不同。以下是主要的差异：

| **特性**     | **存储单元**                               | **内存单元**                                         |
| ------------ | ------------------------------------------ | ---------------------------------------------------- |
| **定义**     | 存储数据的基本单位，通常指数据存储位置     | 特指计算机内存中的存储单元，通常是一个字节或更小单位 |
| **范围**     | 可以指计算机的任何存储介质，如内存、硬盘等 | 通常只指计算机中的内存（RAM）                        |
| **大小**     | 大小可以变化（通常为字节、字、块等）       | 通常为 1 字节（8 位）                                |
| **存储介质** | 可用于表示内存、硬盘、光盘等多种存储介质   | 主要指内存（RAM），不包括硬盘或其他存储介质          |
| **用途**     | 用于存储不同类型的数据，如程序、文件等     | 主要用于存储 CPU 需要快速访问的数据                  |





## 2.分段寻址机制

**<font color='red'>分段寻址的目的是 确定物理地址！</font>**

**<font color='blue'>*16 在 二进制是左移4位，但是在十六进制是左移1位，别搞混了！</font>**

- 问题1的引出：8086内部运算地址只有16位(二进制)，但是物理地址5位，如何解决寻址空间上的矛盾？
- 问题2的引出：为什么物理地址要设计5位(5位是十六进制，换算成二进制是20位)，而不是4位？
- 问题3的引出：什么是段地址？什么是段地址的基地址？什么是物理地址？什么是偏移地址？
- 问题4的引出：为什么要设计段地址*16 + 偏移地址 = 物理地址 这个公式？好处在哪里？
- 问题5的引出：段地址的值是根据段寄存器获取的，什么是段寄存器？有那些种类?

```
问题1的解答：通过段地址左移4位(*16) + 偏移地址  这样就变成了一个20位的地址，可以任意访问整个1MB的存储空间！
问题2的解答：就好比你给一个数据划分内存，肯定是刚好差不多就可以，过大过小都不好，选择5位自然是大佬实践得出的真理！不要抬杠！
问题3的解答：
		段地址：是一个16位的值，段地址 是由段寄存器（如 CS、DS、SS、ES）的值决定的。段地址本质上是指向内存中某个段的基地址
			   段地址的值是根据段寄存器获取的。
		基地址：是段的起始地址（即段地址左移四位就是基地址）。通过基地址与偏移地址的结合，8086 生成了 20 位的物理地址。
		物理地址：每一个内存单元在内存空间中都有唯一的地址，这个唯一的地址被称为物理地址
		偏移地址：相对于段起始地址（基地址）的偏移量，表示在某一个段内的具体位置，用于定位段内的某个字节数据。
问题4的解答：通过段地址左移4位(*16) + 偏移地址  这样就变成了一个20位的地址，可以任意访问整个1MB的存储空间！
		   还可以给不同的段分配不同的功能。
问题5的解答：
		段寄存器是 8086 处理器中专门用于存储段地址的寄存器，负责指向内存中的不同段（如代码段、数据段、堆栈段等）的起始地址。每		  个段寄存器都是 16 位宽，与偏移地址结合后生成 20 位物理地址，用于访问实际的内存单元。
		
		通过下面这些寄存器，8086 实现了对1MB 内存空间的灵活管理和访问。
        CS（代码段寄存器）：指向当前程序代码所在的段。
        DS（数据段寄存器）：指向全局数据或变量所在的段。
        SS（堆栈段寄存器）：指向堆栈所在的段，用于函数调用、返回值等。
        ES（额外段寄存器）：指向额外的段，用于特殊操作（如字符串处理）。
```

## 6. 在代码段中使用数据

- **问题：之前我们都是直接操作 内存地址，但实际上有的内存地址我们不应该随便操作，操作不当可能使错误数据代码出现在不该出现的内存地址。因此，直接操作内存地址有潜在的风险。**

- 解决：我们使用 `dw`（define word）指令来声明数据，操作系统会自动为这些数据分配内存地址

  - ```
    code segment
    	dw 0123H,0456H,012fH
    ```

- 新的问题，但是上面的代码依然有问题，那就是默认IP=0000,我们无法知道哪里是声明的数据，哪里是要执行的代码

- 解决：为了确保程序能够从正确的地址开始执行，我们需要使用汇编中的 `START` 标签，并在程序的 `END` 指令中指定程序入口点

  - ```
    code segment
        
    start:   ;start 用来声明 程序从此处开始
        mov ax, 0x4C00  
        int 21h
    code ends  
    
    end start   ；end start 声明 程序的结束
    ```

  - 为什么 `start` 和 `end start` 不需要包围 `code segment` 和 `code ends`???????

    ```
    这里需要澄清的一点是，start 和 end start 是程序的入口标志，它们并不需要“包围”代码段。start 只是一个标签，表示程序执行的起始位置，而 end start 告诉汇编器程序从哪里开始执行。
    
    start: 标签通常位于程序中的实际执行位置，可以位于 code segment 和 code ends 之间，也可以位于 code segment 的外部。
    end start 并不是标记 code segment 的结束，而是指示汇编器在链接过程中将 start 作为程序入口点。
    ```

### 1. 处理字符问题

**<font color='blue'>如下图所示，也就是说  大写字符 和 小写字符 在二进制的区别就是：小写字符的xx1x xxxx 的第六位一定是1，大写字符则为0 ；所以十六进制中 小写字符Ascii = 大写字符Ascii + 20H</font>**

![image-20241216134922832](https://zlc-typora.oss-cn-hangzhou.aliyuncs.com/img1/image-20241216134922832.png)



**<font color='red'>如何实现 一个字符串 全都大写 或者   小写？？？</font>**

- 很简单吧，与运算  和  或运算  就可以完美解决

-  **原理不难，你自己手算一写就出来了,利用与运算或运算将 第六位永远置为0/1，不影响其他位，就可以实现**

- 下面使用汇编语言进行一波演示

  - ```
    assume cs:code, ds:data
    data segment
    	db 'zlcWcNl'
    	db 'awdDWdwjW'
    data ends
    
    code segment
    start:
    ;  初始化寄存器
    	mov ax,data
    	mov ds,ax
    	mov bx,0
    	
    ;  利用与运算实现字符串全部大写 
    	s1:mov al [bx]
    	and al, 11011111h    或运算就是： or al,00100000h
    	mov [bx],al
    	inc bx
    	loop s1
    
    	mov ax,4c00h
    	int 21h
    code ends
    end start
    ```
