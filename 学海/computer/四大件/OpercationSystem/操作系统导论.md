# 一、虚拟化

```
个人认为OS最关键的两个作用，第一就是将硬件资源转化成虚拟资源，允许程序使用，比如提供系统调用，让程序访问硬件资源
  				 		第二提供安全，高性能的系统调用系统。核心就是安全 与 高性能
```







## 1.CPU虚拟化





### ①  受限直接执行



- 引出问题：

```
OS是如何让一个CPU（假如只有一个CPU）让多个进程感觉是在分别各自占有一个独立的CPU呢？
最简单的思路就是让一个进程运行一段时间，然后运行另一个进程
这里面有两个大问题！
1. 如何高效虚拟化CPU？      
2. 如何保证OS对系统的控制？  一个进程可以访问硬件资源，那如果恶意访问或者不释放控制权怎么办呢
```



- 解决高效率问题：

- ```
  所谓的受限直接执行，就是一种机制。
  当程序加载到内存，直接让CPU运行程序，但是在用户态运行，无法访问硬件资源
  当程序发生中断或系统调用，就会切换到内核态，此时可以访问硬件资源，完成后返回用户态。
  ```



- 解决安全问题：

- ```
  当程序发生中断或系统调用，进入内核态，OS怎么知道要跳转到哪里处理中断？
  会有一张表记录，也就是哈工大OS那里提到的中断向量表之类的一张表，当机器启动时，初始化中就会初始化该表，告诉机器发生中断要怎么做
  ```

  

- 如何保证OS重获CPU的控制权

- ```
  假如一个程序已经进入到内核态，但是OS如何重新获取CPU的控制权，进行一些操作比如暂停该进程，切换别的进程运行？
  时钟中断：
  	每隔几毫米产生一次中断，会让当前运行的进程暂停。
  	
  时钟中断让内核有能力“打断”正在运行的程序，从而定期重新获得 CPU 的控制权
  ```

  



### ② 调度

```
周转时间，追求的是任务如何高效率的完成。但是响应时间差
响应时间，追求的是交互性。但是周转时间差
你想象一下，你使用的电脑，运行一个程序10s后才运行，因为前面要运行高效率的任务导致你当前的任务被推迟了，用户交互性肯定非常差劲
```



- **第一类：以周转时间为标准**
- 周转时间 = 完成时间 - 到达时间
  - FIFO（先进先出）
  - SJF（最短时间优先）：
  - STCF（最短完成时间优先）：



- **第二类：响应时间为标准**
- 响应时间 = 首次运行时间 - 到达时间
  - RR（轮转调度）：每过时钟中断周期的倍数，切换下一个任务执行（这不就是时分共享CPU的具体实现吗）



```
第一类和第二类都有一个核心问题没有解决，那就是OS其实不能看到一个程序什么时候才能执行完，也不知道该程序是否有IO操作
```

- **第三类：多级反馈队列**

  - MLFQ（多级反馈队列）

    ```
    概念：
    	划分多个不同优先级的队列，最顶级的队列通常服务于交互式程序，最底层的队列通常服务CPU密集的程序，因为要大量占用CPU
    实现：
    	划分多个不同优先级的队列，每个队列内部实行RR机制，当一个工作进入后，默认当做短工作任务将其放入最高优先级最列，近似
    	于SJF/STCF，使用完其当层的时间配额则降级，每隔一段时间将所有任务扔到最高级。   
    机制：
    	规则1：如果A的优先级>B，运行A          （不在同一个队列）
    	规则2：如果A的优先级=B，轮转运行A,B    （在同一个队列）
    	规则3：工作进入系统，默认放在最高优先级   （实现SJF/STCF，保证周期时间）
    	规则4：一旦工作用完了其在某一层的时间配额降级  
    	规则5：经过一段时间S，将系统中所有任务添加到最高优先级队列   （防止最底层的任务没有进展）
    ```

  - 总结，MLFQ，就是根据观察一个进程的运行行为来进行调度分配。

  - MLFQ可以满足各种工作的需求：短任务享受类似SJF/STCF的性能；同时也对长时间运行的CPU密集型任务进行合理分配；
                                                             也让交互式任务更长时间保证在高优先级队列中

## 2.内存虚拟化





### ① 地址转换



- 基于硬件的地址转换

  ```
  此处说的地址转换，准确来说是基于硬件的地址转换！
  硬件对每次内存访问进行处理(即指令获取，数据的读取与写入)，都把指令中的虚拟地址转换为数据实际存储的物理地址。
  也就是说每次内存引用时，硬件都会进行地址转换，将虚拟地址->物理地址。
  ```

- 动态重定位

  ```
  1950年，当地址转换首次应用时，当时计算机CPU都会有两个寄存器，基址寄存器和界限寄存器。
  physical address = base + virtual address
  假如OS为一个进程分配了16KB的空间资源，OS选择32KB作为基址，则 base = 32kb 界限寄存器 = 16KB  
  对于进程，地址就是virtual address，每次都从0开始，但是对于硬件来说地址会转换成真实有效的物理地址
  【以上就是当年简单的转换机制】
  ```

- 补充

  ```
  操作系统必须记录那些内存属于空闲状态，有很多不同的数据结构可以用于这项任务
  比如最简单的free list，就是一个列表，记录当前没有使用的物理内存范围
  ```

- 缺点

  ```
  1.通过基址、界限寄存器分配空间，虽然可以做到虚拟内存的效果，但是堆栈之间的空闲区域没有被合理使用，造成大量碎片，效率低下
  2.这样基址加界限的方式会导致空闲内存也占用了实际物理内存
  ```

  

### ② 分段

- 三个基础的逻辑段

  ```
  1.代码段
  2.栈段
  3.堆段
  ```

- 如何分段？

  ```
  之前是给CPU，准确的说是CPU中的MMU分配一对基址界限寄存器，现在我们给每一个逻辑段分配一对基址界限寄存器。
  每个进程都有自己的段表，通过查表访问对应的段，即可实现内存访问，比如对数据的写入获取，或者获取指令。
  
  分段的基本原理：系统运行时，将地址空间中的不同段重定位到物理内存中。
  
  相比之前节省了大量空间，但是将空间分段切成不同长度的分片一定会导致空间本身碎片化，尽管可以通过定位算法不断优化，但是碎片问题始终无法彻底解决。
  ```
